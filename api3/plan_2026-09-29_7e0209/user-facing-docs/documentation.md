# Documentation

Docusaurus Documentation turns your Markdown and MDX files into a structured, navigable knowledge base. It’s designed for technical writers and developers who want to publish guides, references, and manuals without maintaining custom navigation.

## What you can do

Use Documentation to:

- Write and manage content in Markdown and MDX
- Organize documents into folders, categories, and sidebars
- Create automatic sidebars based on folder structure or manual sidebars for custom order
- Add tags to group related content
- Let readers move between documents with previous and next links
- Publish versioned snapshots of documentation for different releases
- Hide drafts and unlisted content from general navigation

## Sidebars and navigation

Sidebars give readers a consistent way to browse your docs. Docusaurus supports two main sidebar styles:

- **Autogenerated sidebars** reflect your folder structure. Each folder becomes a category, and file order is determined by document position settings or filename number prefixes.
- **Manual sidebars** let you choose exactly which documents appear and in what order.

You can set a sidebar position for any document in its front matter. When you don’t provide a position, Docusaurus can use a number prefix from the filename if number prefix parsing is enabled.

If your site has multiple sidebars, you can also choose the sidebar where a document should appear for navigation.

### Document overviews

Some documents are treated as folder overviews. Typical index documents, such as a document named after its folder, become the introduction to a category in autogenerated sidebars. Their links don’t end with a confusing index suffix.

## Tags and categories

Tags help you group documents that share a topic, such as “getting started” or “troubleshooting.” Each tag creates a browsable collection so readers can find related content in one place.

Categories group documents in a sidebar. With autogenerated sidebars, each folder becomes a category automatically. You can link a folder overview document as the category introduction.

## Front matter options

Each document supports front matter settings that control how it appears and behaves. Common options include:

- **Title and description** — used in page titles, search previews, and navigation
- **Sidebar label and position** — control how the document appears in the sidebar and where it sits
- **Displayed sidebar** — choose a specific sidebar when multiple sidebars exist
- **Slug** — define the document’s URL ending
- **Tags** — assign tags for grouping and discovery
- **Draft and unlisted status** — hide content from production or from navigation
- **Previous and next navigation** — override the default pagination targets
- **Edit link** — point readers to the source file for changes
- **Last update information** — show the author and time of the latest change

If you don’t set a title, Docusaurus falls back to the first heading in the document or the file name. If you don’t provide a description, it uses the opening text as an excerpt.

## Pagination

Docusaurus adds previous and next links to each document based on sidebar order. You can keep the automatic behavior or set custom previous and next targets in an individual document’s front matter. Unlisted documents are omitted from navigation by default.

## Draft and unlisted content

- **Draft documents** appear during development but aren’t published in production.
- **Unlisted documents** are published and accessible by direct link, but they don’t appear in sidebars or pagination.

Use these states while a document is still being refined or when you want to share content without adding it to the main navigation.

## Versioning

Documentation supports versioned snapshots. You can tag a version to preserve the current state of your docs. Readers can then browse content for a specific release while you continue working on the next version.

## Translations

Docusaurus Documentation can be translated into multiple languages. Each language can have its own localized version of a document while keeping the same structure and navigation.

## Boundaries

- Documentation content is managed separately from blog posts and standalone pages.
- A document belongs to the Documentation area and uses its own sidebar, tags, and versioning rules.
- Autogenerated categories derive from folder names and document positions, not from blog or page structures.
