# Documentation Internals — Components

This reference covers the internal modules, data flow, and extension points of the `@docusaurus/plugin-content-docs` package. The package is implemented under `packages/docusaurus-plugin-content-docs/src` and turns Markdown files plus sidebar configuration into versioned, routable documentation content.

Source paths in this document are relative to the repository root and use the `main` branch.

---

### Number prefix parsing

The default parser is `DefaultNumberPrefixParser` defined in `src/numberPrefix.ts`. The type signature for a custom parser is:

```ts
export type NumberPrefixParser = (filename: string) => {
  filename: string;
  numberPrefix?: number;
};
```

Users can set `numberPrefixParser` to `true`, `false`, or a custom function. In `PluginOptions`, this is normalized to a function.

## Content loading and data flow

The package loads docs content in several passes, then converts the loaded shape into client-facing props.

### Loaded content

The server-side plugin result uses `LoadedContent`:

```ts
export type LoadedContent = {
  loadedVersions: LoadedVersion[];
};
```

Each `LoadedVersion` includes the version metadata, all docs, draft docs, and the resolved sidebars:

```ts
export type LoadedVersion = VersionMetadata & {
  docs: DocMetadata[];
  drafts: DocMetadata[];
  sidebars: import('./sidebars/types').Sidebars;
};
```

### Doc metadata shape

`DocMetadataBase` is the foundation:

```ts
export type DocMetadataBase = LastUpdateData & {
  id: string;
  version: string;
  title: string;
  description: string;
  source: string;
  sourceDirName: string;
  slug: string;
  permalink: string;
  draft: boolean;
  unlisted: boolean;
  sidebarPosition?: number;
  editUrl?: string | null;
  tags: TagMetadata[];
  frontMatter: DocFrontMatter & {[key: string]: unknown};
};
```

`DocMetadata` adds navigation and sidebar association:

```ts
export type DocMetadata = DocMetadataBase &
  PropNavigation & {
    sidebar?: string;
  };
```

Navigation is a pair of lightweight links:

```ts
export type PropNavigationLink = {
  readonly title: string;
  readonly permalink: string;
};

export type PropNavigation = {
  readonly previous?: PropNavigationLink;
  readonly next?: PropNavigationLink;
};
```

`PropNavigationLink` is a subset of another doc's metadata. Previous and next can be explicitly disabled through a doc's `pagination_prev` or `pagination_next` front matter by setting either to `null`.

### Front matter

Doc front matter is typed as `DocFrontMatter`, a large interface covering slug, title, sidebar behavior, tags, TOC, pagination, edit URL, draft and unlisted flags, number prefix parsing, and last update data.

A few notable fields:

```ts
export type DocFrontMatter = {
  id?: string;
  title?: string;
  tags?: FrontMatterTag[];
  slug?: string;
  sidebar_label?: string;
  sidebar_position?: number;
  sidebar_class_name?: string;
  sidebar_custom_props?: {[key: string]: unknown};
  displayed_sidebar?: string | null;
  pagination_label?: string;
  pagination_next?: string | null;
  pagination_prev?: string | null;
  custom_edit_url?: string | null;
  parse_number_prefixes?: boolean;
  draft?: boolean;
  unlisted?: boolean;
  last_update?: FrontMatterLastUpdate;
  // plus toc, image, keywords, hide_title, etc.
};
```

## Slug computation

Slug generation is centralized in `packages/docusaurus-plugin-content-docs/src/slug.ts` and exported as the default function `getSlug`.

Inputs:

```ts
{
  baseID: string;
  frontMatterSlug?: string;
  source: DocMetadataBase['source'];
  sourceDirName: DocMetadataBase['sourceDirName'];
  stripDirNumberPrefixes?: boolean;      // default true
  numberPrefixParser?: NumberPrefixParser; // default DefaultNumberPrefixParser
}
```

Resolution order:

1. If `frontMatterSlug` starts with `/`, return it as an absolute slug.
2. Compute the directory slug from `sourceDirName`, optionally stripping number prefixes with `stripPathNumberPrefixes`.
3. If there is no `frontMatterSlug` and the source is a category index, use the directory slug.
4. Otherwise, resolve `frontMatterSlug ?? baseID` against the directory slug with `resolvePathname`.

Before returning, the slug is validated with `isValidPathname`. A failure throws an error message that suggests setting a custom `slug` front matter value.

## Sidebar processing

The `src/sidebars` folder implements the full sidebar lifecycle:

1. The sidebar config is loaded.
2. Items are normalized into a consistent internal shape.
3. Autogenerated sidebar items can be produced by `generator.ts`.
4. Items are processed and post-processed.
5. Validation runs to catch invalid references early.

### Sidebar config

The public `SidebarsConfig` type is re-exported from the plugin:

```ts
export type SidebarsConfig = import('./sidebars/types').SidebarsConfig;
```

### Converting sidebars to props

`packages/docusaurus-plugin-content-docs/src/props.ts` converts server-side sidebars and docs into `PropSidebars` for the React theme.

`toSidebarsProp` expects a loaded version with `docs` and `sidebars`:

```ts
export function toSidebarsProp(
  loadedVersion: Pick<LoadedVersion, 'docs' | 'sidebars'>,
): PropSidebars;
```

The conversion logic:

- Builds a `docsById` index using `createDocsByIdIndex`.
- Throws an error when a sidebar references a missing doc id, listing all available document ids:

```
Invalid sidebars file. The document with id "<id>" was used in the sidebar, but no document with this id could be found.
Available document ids are:
- <sorted ids>
```

- Converts doc links with `toSidebarDocItemLinkProp`.

### Link item props

```ts
export function toSidebarDocItemLinkProp({
  item,
  doc,
}: {
  item: SidebarItemDoc;
  doc: Pick<DocMetadata, 'id' | 'title' | 'permalink' | 'unlisted' | 'frontMatter'>;
}): PropSidebarItemLink;
```

The function applies an important precedence rule: **front matter values override sidebar config**. In `toSidebarDocItemLinkProp`, the label and class name resolve as:

```ts
label: frontMatter.sidebar_label ?? item.label ?? title,
className: frontMatter.sidebar_class_name ?? item.className,
customProps: frontMatter.sidebar_custom_props ?? item.customProps,
```

### Category normalization

Categories with doc links or generated-index links are converted into `PropSidebarItemCategory` where `href`, `linkUnlisted`, and `customProps` are resolved from the linked target when appropriate.

## Component props

The package defines several prop shapes consumed by theme components.

### Version metadata props

```ts
export function toVersionMetadataProp(
  pluginId: string,
  loadedVersion: LoadedVersion,
): PropVersionMetadata;
```

`PropVersionMetadata` includes display-oriented version data and the version's docs and sidebars:

```ts
export type PropVersionMetadata = Pick<
  VersionMetadata,
  'label' | 'banner' | 'badge' | 'className' | 'isLast' | 'noIndex'
> & {
  pluginId: string;
  version: string;
  docsSidebars: PropSidebars;
  docs: PropVersionDocs;
};
```

`PropVersionDocs` is a map keyed by doc id:

```ts
export type PropVersionDoc = Pick<DocMetadata, 'id' | 'title' | 'description' | 'sidebar'>;
export type PropVersionDocs = {
  [docId: string]: PropVersionDoc;
};
```

### Tag props

`toTagDocListProp` builds the props for the `DocTagDocListPage`. It resolves tag doc ids to metadata, sorts by title, and maps to `PropTagDocListDoc`:

```ts
export type PropTagDocListDoc = Pick<DocMetadata, 'id' | 'title' | 'description' | 'permalink'>;
export type PropTagDocList = TagModule & {items: PropTagDocListDoc[]};
```

Unlisted docs are filtered out from the tags list page through `toTagsListTagsProp`, which excludes tag values where `tagValue.unlisted` is truthy.

## Client-side context and hooks

### Sidebar context

`packages/docusaurus-plugin-content-docs/src/client/docsSidebar.tsx` provides two exports:

```tsx
export function DocsSidebarProvider({
  children,
  name,
  items,
}: {
  children: ReactNode;
  name: string | undefined;
  items: PropSidebar | undefined;
}): ReactNode;
```

```tsx
export function useDocsSidebar(): ContextValue | null;
```

`useDocsSidebar` returns `{name: string; items: PropSidebar}` or `null`. Because `null` is a valid value (a doc with no sidebar), the context default uses a `Symbol` sentinel:

```ts
const EmptyContext: unique symbol = Symbol('EmptyContext');
```

Calling the hook outside a provider throws `ReactContextError`.

### Contextual search tags

`packages/docusaurus-plugin-content-docs/src/client/docsSearch.ts` exports:

```ts
export function getDocsVersionSearchTag(
  pluginId: string,
  versionName: string,
): string;
```

It returns:

```ts
`docs-${pluginId}-${versionName}`
```

The hook `useDocsContextualSearchTags` computes the relevant version for each docs plugin instance:

```ts
export function useDocsContextualSearchTags(): string[];
```

Version resolution order for each plugin:

1. Active version from `useActivePluginAndVersion`, if the plugin matches the currently active plugin.
2. Preferred version from `useDocsPreferredVersionByPluginId`.
3. Latest version, found in `allDocsData[pluginId].versions` where `v.isLast` is true.

The result is generic and decoupled from any specific search vendor.

## Version metadata

`VersionMetadata` extends `ContentPaths` and includes routing, edit URL, and display data:

```ts
export type VersionMetadata = ContentPaths & {
  versionName: string;
  label: string;
  path: string;
  tagsPath: string;
  editUrl?: string | undefined;
  editUrlLocalized?: string | undefined;
  banner: VersionBanner | null;
  badge: boolean;
  noIndex: boolean;
  className: string;
  isLast: boolean;
  sidebarFilePath: string | false | undefined;
  routePriority: number | undefined;
};
```

Key behaviors:

- `isLast` marks the version selected as the default docs version. It is configurable through the `lastVersion` option.
- `routePriority` is `-1` for the latest docs and `undefined` for other versions, so `/docs/foo` routes after `/docs/<versionName>/foo`.
- The banner is `"unmaintained"` for the version before latest and `"unreleased"` for the version after latest; `banner: "none"` in user options is transformed to `null`.
- Docs are excluded from search engine indexing when `noIndex` is `true`.
